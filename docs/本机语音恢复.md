# 本机语音恢复说明

更新日期：2026-11-09 · 发布文档 v0.2.1。

本次恢复了制作电脑上的 AI 对话中转进程。原网页和 SenseVoice 识别服务仍在运行；中转停止时，界面可以正常打开，实时 DM 却无法回复。恢复没有更换模型、音色或密钥，也没有部署公网后端。

## 两套服务不要混用

| 场景 | 工程与入口 | 说明 |
| --- | --- | --- |
| 原制作电脑 | 原 `echo-theatre` 工程，网页 4177、识别 4178、AI 中转 4179 | 原本机配置和模型已安装；本机识别使用 SenseVoice |
| 本公开仓库 | 仓库中的 `backend/`，默认 4185 | 仅用于受邀公共 DM，需要单独配置密钥、邀请码、HTTPS/WSS 和内网 TTS 路由 |

本公开仓库的 `backend/scripts/dining-session.mjs` 与 `dining-context.mjs` 已和本机核心实现一致。重启本机服务不会修改 GitHub 的运行状态；GitHub Pages 只发布静态文件。

## 原制作工程怎样恢复

在终端进入原 `echo-theatre` 工程目录后执行以下命令。这个命令不在本公开仓库根目录运行：

```sh
npm run dev -- --port 4177 --strictPort
```

它会检查并启动网页、识别与 AI 中转。若网页已由原来的后台任务运行，不要再启动一套占用相同端口的进程。

制作电脑原先已安装 macOS 后台任务 `local.echo-theatre.dev`，可用以下命令整体重启；网页会短暂断开，刷新后继续：

```sh
launchctl kickstart -k "gui/$(id -u)/local.echo-theatre.dev"
```

此命令仅适用于已经安装该任务的电脑，不是新电脑安装步骤。若网页与识别正常、只有 AI 中转停止，也可在原工程目录单独启动：

```sh
node scripts/nia-server.mjs
```

单独启动时需保持终端进程运行。若提示端口被占用，先检查已有服务，不重复启动。原启动器目前不会自动重启单独退出的 AI 中转；此次没有新增进程守护机制。

## 怎样确认恢复

```sh
curl --fail http://127.0.0.1:4177/api/voice/status
curl --fail http://127.0.0.1:4177/api/nia/status
```

识别应返回 `ready:true`，AI 中转应返回 `configured:true`。后者仅说明本机配置存在，不能证明账号额度、网络或回复可用。还需要在游戏中实际提问，确认文字与主持语音返回；使用麦克风时再检查转写结果。真人识别准确率和听感需实际体验。

## 如果要让 GitHub 在线页也能说话

按[语音部署说明](语音部署说明.md)部署 `backend/`，使用能访问内网 TTS 的服务器、有效 HTTPS 域名和 WebSocket 反向代理，再设置仓库变量 `DM_API_BASE` 并重新构建 Pages。启用后必须检查真实问答、声音、停止和错误恢复。

密钥只填后端本机配置。不要上传 `.env.local`、模型缓存、电脑日志、邀请码或私人剧本；也不要将这些内容填入前端 `VITE_` 变量。
