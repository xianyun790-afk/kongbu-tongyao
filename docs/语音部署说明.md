# MiniMax 语音与公共 AI DM · v0.2.1

更新日期：2026-11-09。

制作电脑已通过重启已有进程恢复 SenseNova 问答与 MiniMax 语音。公开后端的核心会话与资料核对代码已与本机一致，本轮无需用本机通用服务覆盖公开后端。运行进程属于各自机器，不能随代码 push 到 GitHub。[本机恢复方法](本机语音恢复.md)另列于独立说明。

**当前 GitHub Pages 仍运行预设文字模式，不能使用在线语音**，因为尚无可访问内网语音测试台的公网 HTTPS/WSS 后端。部署并验收该后端后才能启用在线实时对话。

## 接入内容

- 回答：SenseNova-V7.0-omni，仅担任公共 DM；理解最近对话、只引用已公开的三组材料。六个角色留给真人。
- 声音：MiniMax `speech-2.8-hd`，`Chinese (Mandarin)_Radio_Host`（电台男主播）。只合成通过资料核对的回复，不再播放 NIA 的内置声音。
- 输入：启用后端后的在线版使用浏览器的中文 SpeechRecognition，需主动点击麦克风，可能连接浏览器厂商的在线识别服务。无支持、无权限或网络失败时可以打字。制作电脑上的原工程已改用本机离线 SenseVoiceSmall-int8-2024-07-17；这套本机转写服务没有随 GitHub Pages 发布。
- 取消：停止或新问题会中止旧合成；过期回复按 turn_id 丢弃。语音失败保留文字并提示，实际音频播放结束后才结束播报状态。
- 范围：这是单浏览器试玩，不含六人联机房间、服务端共同记忆或私人角色分发。

语音测试台只提供 TTS 和声音克隆，不是 ASR 或聊天模型接口。本项目使用现成音色，没有训练或克隆任何人的声音。

## 部署前必须具备

1. 使用有额度和模型权限的 SenseNova 账号。当前本机配置已经恢复；服务器应另行填写有效密钥。密钥只放后端环境。
2. 一台能访问你所提供内网语音测试台的服务器，加一个有效的 HTTPS 域名，反向代理必须支持 WebSocket。

普通公网云服务器通常访问不到企业内网 IP。必须先让部署机器接入允许的内网路由，或由语音服务维护者提供授权的 HTTPS 服务入口。只部署 GitHub Pages 或把内网 IP 换成 HTTPS 字样都不能解决。

## 运行独立后端

把仓库的整个 `backend/` 目录交给部署者。Node.js 24：

```sh
cd backend
npm ci --ignore-scripts
cp .env.example .env.local
```

在服务器本机编辑 `.env.local`：填现有 NIA AK/SK、实际 `DINING_TTS_BASE_URL`，保留 MiniMax 模型及音色。不要把该文件上传仓库。

用密码管理器或以下命令生成邀请码，并填入 `DINING_DEMO_TOKEN`（24–256 字节）：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
npm test
npm start
```

进程默认只监听 `127.0.0.1:4185`。用 `backend/nginx.example.conf` 配置 HTTPS 域名与有效证书，再由 systemd 等进程管理器保持服务运行。Dockerfile 也已提供；容器运行时注入环境变量，只把容器端口绑定到服务器 loopback。

```sh
curl https://你的后端域名/health
curl https://你的后端域名/api/nia/status
```

`configured:true` 仅表示密钥存在，不代表额度有效。必须实际提问并收到非空文字与音频，再判定部署成功。

## 启用 GitHub Pages

在 GitHub 仓库 Settings → Secrets and variables → Actions → Variables 添加：

- 名称：`DM_API_BASE`
- 值：`https://你的后端域名`，不要填语音测试台地址、AK/SK 或邀请码。

重新运行 Deploy game demo to GitHub Pages。工作流会构建前端并启用 HTTPS 状态检查、WSS 对话及语音入口。变量为空时继续使用明确标记的预设文字模式。

测试者打开完整邀请链接：

```text
https://xianyun790-afk.github.io/kongbu-tongyao/#dm_token=你的邀请码
```

连接码从 URL 片段读取后立即移除，保存在本次浏览器会话，只有连接 WSS 时发送。它不会写入 JS 构建或仓库。只分享给受邀测试者；这是共享测试码，不是正式用户账号体系。更换服务端邀请码可撤销旧邀请。

## 部署验收

- HTTPS 页面检查状态并建立 WSS，桌面与手机分别试一次。
- 第一次进入听主持开场；打字提问后能听到电台男主播，连续追问沿用已公开线索。
- 点击麦克风后说中文，确认转成文字、发送、播报；权限拒绝与识别不可用时仍可打字。
- 停止、连续新问题、切换房间后不响起旧语音；播放完字幕按现有规则收起。
- 不公开磁带时主持人不泄露内容；不代替真人角色，也不自动推进。
- 关闭语音服务、耗尽额度时如实报错，预设提示有明确标签。

后端只开放餐厅 DM，不代理语音测试台管理、声音克隆、文件上传、任意 TTS 或旧通用 NIA 会话。限制来源、邀请码、并发和每日请求。用量计数保存在进程内，重启会重置；持久消费上限应另由模型服务账号设置。反向代理不要记录包含邀请码的 WebSocket 查询字符串。
